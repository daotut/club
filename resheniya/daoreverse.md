# Как разобрать чужую механику без исходников: REA, лёгкая альтернатива и наш `daoreverse`

> Готовое решение библиотеки DAO CLUB. Задача: понять, как устроено у конкурента — сайт, воронка,
> трекинг рекламы, виджет, приложение — **с доказательствами**, и описать, как собрать то же у себя.

## Задача, которую решаем

«Как они считают заявки из рекламы, если человек уходит в Telegram?», «что этот виджет отправляет
на сервер?», «как устроена их воронка?» — обычно на такие вопросы отвечают с чужих слов или по
внешнему виду страницы. Агент на ИИ может сам открыть страницу, записать, что она отправляет,
прочитать её скрипты и собрать ответ, где у каждого утверждения есть источник.

Для этого нужен не «умный промпт», а набор инструментов и порядок действий. Ниже три варианта,
которые мы сравнивали, и почему остановились на своём.

## Вариант 1. REA — Reverse Engineer Anything

Открытый проект: MCP-сервер и CLI для агента — https://github.com/morluto/rea (MIT).

| | |
|---|---|
| Что внутри | 207 инструментов, пакет npm ~25 МБ, ~72 КБ инструкций для модели |
| Сильная сторона | глубокий разбор программ: дизассемблер, декомпиляция, нативный код |
| Цена | тяжёлый контекст. По замеру автора лёгкой альтернативы, если подгрузить все инструменты REA сразу, один ответ «OK» стоит ~400 тыс. токенов и $1,60 |
| Вывод | мощный инструмент для реверса программ; для сайтов и воронок — избыточен |

## Вариант 2. leanrea — один файл вместо сервера

Открытый скилл (MIT) размером 8 КБ — https://github.com/aicodeking/leanrea. Автор прочитал исходники REA и свёл каждую функцию к обычной
команде, которая и так есть на компьютере. Агент сам запускает эти команды.

| | |
|---|---|
| Как устроен | правила работы + роутер «тип цели → самая быстрая команда» + готовые «первые ходы» |
| Замер автора | на 38% быстрее и на 35% дешевле REA при той же точности (74 из 75 против 75 из 75) |
| Оговорки автора | 3 прогона на задачу, одна модель, один компьютер; голая модель почти так же точна — выигрыш прежде всего против тяжёлого REA |
| Слабое место | раздел про сайты — одна строка. Скилл писали для программ, а не для воронок |

## Вариант 3. `daoreverse` — наше решение

Мы взяли роутер leanrea для программ и дописали то, чего не хватало под задачи предпринимателей,
у которых почти все цели — сайты, лендинги и рекламные связки.

**Что внутри:**

1. **Свой инструмент для сайтов** `web-trace` (на Playwright). Открывает страницу как обычный браузер
   и записывает: все запросы с телами и ответами, сохранённые скрипты, куки до и после клика,
   WebSocket-соединения, переходы в мессенджеры (`tg://`, `t.me`, MAX, WhatsApp). Два прогона —
   «загрузка» и «клик по кнопке» — и видно, что именно уходит наружу в момент заявки.
2. **Роутер для всего остального** — Electron-приложения, программы Mac, Go/Rust, Android, базы
   SQLite, HAR-файлы: первый ход одним вызовом, без перебора.
3. **Метки доказательности** у каждого утверждения: *видел* (есть запрос, файл, строка кода),
   *вывод* (следует из увиденного), *неизвестно* (не нашёл — не значит «нет»).
4. **Обязательный раздел «как собрать у себя»** — разбор заканчивается не пересказом, а планом:
   из каких своих частей собрать ту же механику и чего из неё не брать.
5. **Рамка легальности** — только публичные страницы и свои системы, без обхода авторизации, оплаты
   и защиты, без фальшивых кликов в чужую рекламную статистику.

**Чем лучше для наших задач:**

| | REA | leanrea | `daoreverse` |
|---|---|---|---|
| Сайты, воронки, трекинг | общие инструменты | одна строка | свой инструмент: сеть, скрипты, сокеты, deeplink |
| Вес для контекста модели | очень тяжёлый | лёгкий | лёгкий |
| Установка | MCP-сервер, npm | один файл | одна фраза своему ИИ-агенту |
| Форма результата | свободная | метки seen / inferred / unknown | метки + «как собрать у себя» |
| Глубокий реверс программ | ✅ сильнее всех | базовый | базовый (как leanrea) |

Честно: если нужно разобрать нативную программу через декомпилятор — REA сильнее, мы это не мерили
и не спорим. Для сайтов, воронок и рекламных связок `daoreverse` даёт больше с меньшими затратами.

## Пример: как трекер понимает, что человек из рекламы ушёл в Telegram

Разбор одного сервиса атрибуции занял три прогона и чтение двух скриптов по 10–12 КБ. Механика
по шагам:

1. На лендинге стоит скрипт сервиса, он находит ссылки на Telegram-чат и вешает свой обработчик. — *видел*
2. По клику уходит цель в Яндекс Метрику и запрос на сервер сервиса с идентификатором посетителя Метрики. — *видел*
3. Сервер отвечает ссылкой-deeplink, страница открывает Telegram. — *видел*
4. Параллельно страница открывает WebSocket на 10 минут и исполняет код, который пришлёт сервер. — *видел*
5. Когда человек написал в чат, сервер присылает в ещё открытую вкладку код с целью Метрики — конверсия
   ложится в тот же визит. — *вывод* (из кода и названий функций)
6. Как сервер связывает сообщение в чате с кликом — *неизвестно* (серверная сторона).

И раздел «как собрать у себя»: тот же результат даёт свой бот со стартовым параметром и загрузка
офлайн-конверсий по идентификатору Метрики — без исполнения чужого серверного кода на своей странице.
